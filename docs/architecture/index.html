③ 노트 저장 시퀀스

저장 버튼 클릭부터 목록 리렌더까지. 낙관적 업데이트 없이 API 응답을 받은 뒤에 로컬 상태를 갱신한다. 

sequenceDiagram
  actor U as 사용자
  participant E as NoteEditor
  participant C as NotesContext
  participant A as api/notes.ts
  participant S as json-server
  participant L as NoteList

  U->>E: 저장 클릭
  E->>E: 제목 비었으면 alert 후 중단
  E->>E: setSaving(true)
  alt isCreating (새 노트)
    E->>C: addNote(title, content)
    C->>A: createNote(title, content)
    A->>S: POST /notes (createdAt, updatedAt 클라이언트에서 생성)
    S-->>A: 저장된 Note (랜덤 문자열 id)
    A-->>C: Note
    C->>C: setNotes 로 목록 끝에 추가
  else 기존 노트 편집
    E->>C: editNote(id, title + content)
    C->>A: updateNote(id, updates)
    A->>S: PATCH /notes/:id (updatedAt 갱신)
    S-->>A: 수정된 Note
    A-->>C: Note
    C->>C: setNotes 로 해당 id 교체
  end
  C-->>L: notes 변경으로 리렌더
  E->>E: onDone() 호출 후 setSaving(false)
  Note over E,S: 실패 시 api 가 throw, NoteEditor 가 catch 해서 alert

분석 메모

  • 순환 의존성 없음. 의존 방향이 Entry → Components → Context → API 한 방향이다.
  • 슬롯 주입: NoteList·NoteEditor 는 App 이 import 하지만 Layout 의 sidebar/main 슬롯으로 들어가 Layout 내부에서 렌더된다. import 그래프만 보면 이 관계가 드러나지 않는다.
  • context 직접 사용: NoteList, NoteEditor 만 useNotes() 를 쓴다. Layout, NoteItem 은 props 만 받는다.
  • API 접근 경로 단일화: api/notes.ts 는 NotesContext 에서만 import 된다.
  • 삭제 에러 미처리: NoteItem → NoteList → removeNote 경로에 try/catch 가 없어서 삭제 실패가 처리되지 않는다.
  • 선택 상태 정리 누락: 선택 중인 노트를 삭제해도 selectedNoteId 가 남는다. 새 노트를 저장하면 isCreating=false, selectedNoteId=null 이 되어 편집기가 빈 화면으로 돌아간다(새 노트가 선택되지 않음).
